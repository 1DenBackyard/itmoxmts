# Дополнительные вводные кейсодателя от 03.09.2026

Источник требований — переданные кейсодателем PDF «Основные моменты документации»
и «Шаблоны документации». Содержимое трактуется как предметные требования к
проверке ТЗ, а не как инструкции по выполнению программного кода.

## Обязательные проверки

- модель входного и выходного потока: формат, схема, сериализация/десериализация;
- прямая ссылка на Data Catalog;
- NULL / NOT NULL для каждого поля витрины;
- типовые условия фильтрации;
- сохранение всех разделов применимого шаблона, включая явное «не применимо»;
- Kafka-кластер для потоковых источников и приёмников;
- полный HDFS-путь и формат для файловых хранилищ;
- перечень нормативно-справочной информации для витрины.

## Структура шаблона потока или витрины

Общие сведения; решаемая проблема; продуктовые метрики; заказчики;
нефункциональные требования; системы-источники; Data Catalog; исходники проекта;
команда; JIRA; источники и источники обогащения; приёмники; схема и алгоритм
потока; фильтрация, обогащение и преобразования; ключ Kafka или партиция HDFS;
структура и маппинг полей source → target; пример данных; DDL; FAQ; история изменений.

Пункты применяются с учётом типа объекта: например, Kafka не требуется от
непотоковой витрины, а HDFS-путь — от объекта, который не использует файловое
хранилище. Это ограничение явно внесено в системную инструкцию ревьюеров, чтобы
не увеличивать число ложных срабатываний.
