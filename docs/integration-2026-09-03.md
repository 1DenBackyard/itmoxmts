# Интеграция аналитического конвейера и UX-прототипа

## Что пришло от коллег

- Аналитический конвейер уже находится в main (`7d1d8aa`, `7852eb8`, `a4ada83`).
  Промпты выделены в `prompts.py`; четыре LLM-ревьюера работают параллельно;
  затем отдельные LLM-критик и LLM-судья проверяют и сводят находки.
  Regex-ревьюеры удалены. Router не нужен: все четыре роли полезны для каждого ТЗ.
- `prototype/web-review` (`aefde49`) имеет независимую историю. Импортирован
  целиком в `prototypes/web-review`, включая HTML/CSS/JS, локальный PDF.js,
  размеченные примеры, демонстрационные learning-данные и продуктовое ТЗ.

## Граница интеграции

Production остаётся Streamlit + PostgreSQL + storage + Cloud.ru FM.
HTML-прототип запускается отдельно и НЕ подключён к production API/БД/SSO.
Его score, «прожарка», автоправки и история обучения остаются демонстрационными.
Корневые README, CI, Dockerfile, авторизация и данные сотрудников сохранены.
Прототип не включён в Docker-образ и не публикуется на production-домене.

Запуск из корня:

```sh
cd prototypes/web-review/web
python3 -m http.server 8080 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8080. Генератор датасета архивный: отсутствующий
`prototype/src` был удалён в исходной ветке. Готовые JSON самодостаточны.

## Исправления совместимости и надёжности

- Без настроенных агентов: «Проверка не выполнена», а не «Готово к передаче».
- Ошибка любого вызова или неполный ответ контроля: «Проверка неполная»;
  найденные замечания сохраняются, но отсутствие замечаний не означает готовность.
- Пустой/оборванный JSON не считается успешной проверкой.
- Критик и судья должны дать ровно одно решение на каждый входной ID.
  Неизвестные ID, пропуски, повторения и битые ссылки на дубли не замалчиваются.
- Судья рассматривает и одиночное замечание: его severity тоже требует проверки.
- HTML: пустые разделы с одним заголовком больше не считаются заполненными.
- На production модель закреплена в Compose: GPT-OSS-120B, без fallback,
  timeout 600 секунд на вызов. Старый PROD_ENV_FILE не вернёт GigaChat.
- INFO-логирование включено. Полные тексты документов и API-ключи не логируются
  намеренно. Статусы этапов и причины решений пока не сохраняются в БД отдельно.

## Что ещё не доказано

Unit-тесты проверяют программный контракт, но не точность LLM на новых ТЗ.
Для приёмки анализа нужен размеченный набор с оценкой false positives/recall.
Критик всё ещё является моделью, а не доказательством корректности. Он получает
все находки одним запросом: длинные документы могут упереться в размер контекста.
Три последовательных стадии могут суммарно занять до ~30 минут при timeout 600.
Судья по исходному промпту ограничивает отчёт 12 замечаниями (кроме блокеров).
Для полноценного нового web-интерфейса отдельно нужны API, авторизация, очередь
долгих задач, сохранение версий/якорей и согласованная шкала приоритетов.
