# Интерфейс production

> Архивное описание Streamlit. Текущая версия: [HTML + FastAPI](html-production.md).

Основной интерфейс остаётся на Streamlit. Из `prototypes/web-review` перенесены
визуальные принципы (красный акцент, светлые карточки, шаги проверки), разбор
замечаний и «Мой прогресс». Статический прототип остаётся самостоятельным демо.

Экран входа ограничен по ширине. После проверки форма загрузки сворачивается,
а результат отображается в двух колонках: исходный текст и замечания.
Исходный текст HTML-экранируется, поэтому не исполняет разметку из документа.
На узких экранах колонки перестраиваются. Базовый чек-лист дополнен требованиями
кейсодателя из двух PDF от 03.09.2026 и доступен даже без истории ошибок.

## Пользовательский путь

1. Войти в личный кабинет.
2. На странице «Проверка ТЗ» выбрать файл или текст, запустить реальный анализ.
3. Отфильтровать замечания по приоритету, решению или поисковой строке.
4. Принять, отклонить или отметить замечание исправленным. Решение можно вернуть
   в открытое состояние. Исходный вердикт не меняется: после правок нужно новое ревью.
5. Скачать JSON-отчёт или открыть последние 10 проверок в «Истории».
6. В «Моём прогрессе» посмотреть подтверждённые категории, долю исправлений и чек-лист.

Все результаты, решения и показатели принадлежат вошедшему пользователю и берутся
из существующей БД. Неподтверждённые гипотезы не входят в персональный профиль ошибок.
Схема БД, авторизация, хранилище и аналитический pipeline не изменены.

## Границы переноса

- Демо-score, «прожарка» и фиктивные автоисправления не включены в production.
- Просмотр извлечённого текста доступен для последней проверки текущей сессии;
  это не PDF-редактор и не постоянное хранение текста в БД.
- Чек-лист — временные отметки сессии, не доказательство исправления документа.
- Доля исправлений основана на решениях сотрудника, а не на автоматической проверке правок.
- При анализе показывается ожидание без выдуманного процента выполнения.
- Выход очищает состояние сессии. Права на чтение и изменение проверяются репозиторием.

UI регрессии покрыты Streamlit AppTest: вход, история, подтверждение и возврат
замечания, персональные показатели, отсутствие ложного успеха при недоступной LLM, выход.
Публикация — существующий GitHub Actions workflow → Cloud.ru VM; новый хостинг не создаётся.
